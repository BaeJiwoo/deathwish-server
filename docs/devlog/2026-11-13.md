## 설계 결정

- Session은 클라이언트 연결 하나를 나타내고, Room은 여러 세션이 참여하는 공간으로 구분한다.
- 각 연결에는 별도 GameChannelHandler와 ClientSession을 생성한다. 종료한 세션을 재사용하지 않는다.
- 방의 멤버 목록과 세션별 소속 정보는 하나의 잠금 안에서 함께 변경한다.
- 연결 종료 시 세션을 종료 상태로 바꾸고, 방에서 제거한 뒤 세션 목록에서 제거한다.
- 같은 방에 다시 입장하면 중복 등록 없이 성공한다. 다른 방 요청은 기존 소속을 유지하며 거절한다.
- 방은 서버 시작 전에 1번부터 RoomCount번까지 생성하며, 기본값은 2개다. 빈 방도 유지한다.
- 매치 종료 후 방 초기화·재사용은 논의만 했고 이번에는 구현하지 않았다.
- X·Y 정수 입력 송수신은 작업 순서상 보류했다. 처음 작성한 변경은 취소했으며 현재 기능에 포함되지 않는다.
- 설정 우선순위는 실행 인수(주소·포트) → 운영체제 환경변수 → 실행 작업 디렉터리의 `.env` → 코드 기본값이다.
- 설정은 시작 시 읽고 검증한다. `.env` 변경은 재빌드 없이 재시작으로 적용한다.

## 현재 사용 시나리오

프로젝트 루트에서 서버와 MockClient를 각각 실행한다.

```powershell
dotnet run --project src/DeathWish.Server
dotnet run --project mockclient/DeathWish.MockClient.Console -- 127.0.0.1 7777
```

- 접속하면 세션만 등록되고 아직 방에는 속하지 않는다.
- `/join 1`: 1번 방 입장. 반복 요청해도 중복 등록되지 않는다.
- 1번 방에 속한 상태에서 `/join 2`: AlreadyInAnotherRoom.
- 존재하지 않는 방 번호: RoomNotFound.
- 일반 문자열: 요청자에게만 Echo. 같은 방의 다른 클라이언트에 방송하지 않는다.
- `/quit`: 연결 종료, 방 소속 및 세션 목록에서 제거.
- `/leave` 명령, 멤버 목록 전송, 게임 플레이는 아직 없다.

## 검증

- 테스트 프로젝트 및 MockClient Console 빌드: 경고·오류 0개.
- 전체 ConnectionTests 실행: 종료 코드 0 확인.
- 세션 ID 구분, 중복 이벤트, 동시 등록·제거, 채널 그룹 종료 시 잔류 여부 확인.
- 방 중복 입장, 방 변경 거절, 멤버 목록 복사, 동시 입장과 연결 종료 경합 확인.
- 패킷의 정확한 바이트 배열, 분할·연속 수신, 잘못된 길이·방 번호·결과 코드 확인.
- 실제 TCP로 두 클라이언트가 같은 방에 입장하고, 입장 후 Echo도 정상 동작함을 확인.
- 응답 타입·방 번호 불일치, 타임아웃, EOF, 잘린 응답, 서버 전송 실패 처리 확인.
- 실제 서버·콘솔로 대화형 명령과 단일 요청 모드를 실행하고 성공·거절 종료 코드를 확인.
- 방 개수 1개·5개 사전 생성 및 범위 밖 번호, 0 이하 설정 거절 확인.
- `.env` 구문, 설정 우선순위, 기본값, 잘못된 값 거절, 환경변수 비변경 확인.
- `git diff --check` 통과.
- 초기 테스트에서 소켓 접근 제한이 있었으나 이후 실제 TCP 테스트는 통과했다.

검증 명령:

```powershell
dotnet build tests/DeathWish.ConnectionTests --no-restore -m:1 -nr:false -p:UseSharedCompilation=false
dotnet build mockclient/DeathWish.MockClient.Console --no-restore -m:1 -nr:false -p:UseSharedCompilation=false
dotnet tests/DeathWish.ConnectionTests/bin/Debug/net10.0/DeathWish.ConnectionTests.dll
```
