# 개발 기록

개발한 내용과 검증 결과를 날짜별로 기록합니다. 날짜는 한국 시간(Asia/Seoul)을 기준으로 합니다.

## 작성 방식

- 파일명은 `YYYY-MM-DD.md`로 작성합니다.
- 같은 날 작업을 이어가면 기존 날짜 파일을 갱신합니다.
- 구현·수정·검증 작업을 마치거나 리뷰를 요청하기 전에 해당 날짜 기록을 갱신합니다.
- 실제 구현, 설계 결정, 검증 결과, 미완료 작업을 구분합니다. 논의만 한 기능을 구현 완료로 기록하지 않습니다.
- 실행하지 않은 테스트나 확인하지 않은 커밋·푸시는 완료로 기록하지 않습니다.
- 커밋이 확인되면 해시와 제목을 추가합니다. 기록을 남긴다는 이유만으로 커밋하지 않습니다.
- 설정 예시는 공개 가능한 값만 사용하고, `.env`의 비밀값은 기록하지 않습니다.
- 새 날짜 파일을 만들면 아래 목록에 최신 날짜부터 링크를 추가합니다.

## 기록 양식

```markdown
# YYYY-MM-DD 개발 기록

## 목표

- 오늘 진행할 작업

## 개발 항목

| 항목 | 변경 내용 | 상태 |
| --- | --- | --- |
| 기능명 | 실제 변경 내용 | 구현 / 검증 / 리뷰 대기 |

## 설계 결정

- 결정한 내용과 이유

## 검증

- 실행한 명령 또는 시나리오와 결과
- 실행하지 못한 검증과 제한 사항

## 관련 커밋

- 확인된 해시와 제목 또는 미커밋 상태

## 남은 작업과 다음 시작점

- 미완료 작업
- 다음 작업을 시작할 위치
```
