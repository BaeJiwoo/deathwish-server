## BepuPhysics 전환

- 사용자 요청에 따라 미커밋 수동 충돌 판정과 테스트를 BepuPhysics 2.4.0 기반 서버 시뮬레이션 및 동작 테스트로 교체했다. 평면은 위쪽에서 충돌하는 두 삼각형으로 구성했다. 플레이어 바디는 회전을 잠근 0.65 × 1.8 × 0.65 m 상자이며 XZ 속도와 발 좌표를 통해 제어한다. 플레이어끼리의 충돌은 제외했다.
- 30 Hz에서 4 m 높이, 초기 하강 속도 200 m/s로 시험했다. 초기 접촉 강성에서는 첫 틱에 약 4.5 cm 파고들어 검증이 실패했다. 접촉 주파수를 120 Hz로 조정한 후 1 cm 허용 오차의 매 틱 관통 검사와 최종 착지 높이 검사를 통과했다.
- Windows에서 `dotnet run --project tests/DeathWish.ConnectionTests` 종료 코드 0. 일부 걸친 상태에서 60틱 지지, 바닥 끝 이탈, 입력 해제 후 계속 낙하, 중력 0 및 기존 TCP 회귀 통과.
- 엔진 전환 단위는 미커밋 리뷰 대기. 실제 GameWorld 입퇴장·월드 틱과 스냅샷 연결은 다음 목표다. Linux 실행과 다수 방에서의 비용은 미검증이다.

- 기존 단계도 Bepu에 맞춰 수동 Gravity.Apply와 PlayerState의 중복 수직 속도를 제거했다. 설정된 중력은 GameServer → RoomManager → Room → GameWorld를 거쳐 시뮬레이션 생성에 사용된다.
- BoxCollider와 PlaneCollider가 배치 정보를 Bepu 정적 도형으로 등록한다. 시뮬레이션 생성 시 월드의 충돌체 목록 전체를 사용하며, 배치 정보는 생성 시점에 복사한다.
- Windows 연결 테스트 전체 통과(종료 코드 0). 중력 8에서 두 틱의 속도와 높이, 중력 0에서의 등속 낙하, 서로 다른 위치·높이의 평면과 상자 두 개에 각각 착지하는 동작을 검증했다. 발 좌표 비교는 중심 좌표 변환 시 관측된 부동소수점 반올림을 고려해 0.00001 m 오차를 허용했다.

## Unity 클라이언트 낙하 표시

- 실제 deathwish-client 프로젝트와 재설치용 SyncTestClient의 격자 바닥을 원점의 10 m × 10 m 평면에 맞췄다. 로컬·원격 캐릭터는 서버 스냅샷의 발 좌표를 그대로 사용한다. 씬 검증 코드에 실제 바닥 경계와 음수 Y 표시 검사를 추가했다.
- Unity 6000.3.11f1에서 실제 SyncTestScene을 Play 모드로 실행하고 로컬 서버에 TCP로 접속했다. 자동 이동 입력으로 가장자리 밖으로 걸어 나온 후 정지했다. 바닥 렌더러 중심 (0, 0, 0), 반크기 (5, 0, 5)를 확인했다. 캐릭터가 X = 7.17 m에서 Y = −2.52 m에서 −6.11 m로 계속 떨어졌고 카메라 오프셋이 유지됐다.
- 실제 키보드 입력, 원격 Unity 인스턴스의 동시 표시, 독립 실행 빌드는 이번 실행에서 검증하지 않았다. 변경은 커밋 전 리뷰 대기 상태다.

## 바닥 확장 및 Unity 스냅샷 보간

- 서버와 Unity 표시 바닥을 원점 중심의 100 m × 100 m로 확장했다. 로컬·원격 캐릭터는 최신 스냅샷 좌표까지 100 ms 동안 선형 보간한다. 이른 수신은 현재 표시 위치에서 이어가며, 늦은 수신은 마지막 목표 위치에서 대기한다. 카메라는 보간된 캐릭터를 따라가고 좌표 UI와 Scene 기즈모는 서버 원본을 표시한다.
- Unity 6000.3.11f1에서 실제 클라이언트 씬을 열고 합성 스냅샷으로 양쪽 캐릭터의 50 ms 중간 좌표, 카메라, 이른 도착의 연속성, 지연 시 정지, 퇴장과 연결 해제를 검증했다. 렌더러 경계는 X/Z 각각 −50 ~ +50 m였다. 설치본과 배포용 스크립트 내용이 일치했다.
- Windows 서버 회귀 검사 전체 통과(종료 코드 0). 확장된 경계에서 부분 지지·이탈·낙하와 두 TCP 클라이언트의 위치 일치를 확인했다. 이번 보간 검증에는 실제 네트워크 지연 주입과 독립 실행 빌드를 포함하지 않았다.

## Unity Motion Lab 비주얼

- 실제 Unity 프로젝트와 배포용 씬에 흰색 계측 바닥, 파란 트랙, 노란 안전 경계선, 관측창이 있는 외벽을 적용했다. 외벽은 이동 영역 바깥의 렌더링 전용 장식이다. 로컬 캐릭터와 기즈모는 파란색, 원격은 노란색으로 통일하고 접속 패널 배색과 범례도 갱신했다.
- Unity 6000.3.11f1 Play 모드에서 씬 참조, 셰이더, 합성 스냅샷 표시, 카메라 추적, 퇴장·연결 해제를 검증하고 카메라와 Canvas를 함께 렌더링했다. 종료 중 비활성 UI 갱신 오류를 수정한 뒤 재검증을 통과했다. 이번 시각 검증은 합성 플레이어 두 명을 사용했으며 독립 실행 빌드는 실행하지 않았다.
