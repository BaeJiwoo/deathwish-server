# DeathWish 개발 로드맵 — Phase 단위

목표: C# 서버와 Unity 클라이언트를 이용한 Server Authoritative 기반 3D 하이퍼 TPS 데스매치 구현

서버가 이동, 물리, 전투, 애니메이션의 논리적 상태를 관리하고, 클라이언트는 입력 처리와 렌더링을 담당하는 구조입니다.

총 6개 Phase / 15개 Sprint로 구성했습니다.

## 캐릭터 선택 및 고유 스킬

- 플레이어는 캐릭터 3종 중 1종을 선택합니다.
- 각 캐릭터는 서로 다른 고유 액티브 스킬을 1개씩 가집니다.
- 초기 구현에서는 기본 무기, 이동, 체력을 공통으로 사용하고 고유 스킬로 차별화합니다.
- 초기 선택 규칙은 경기 시작 전 선택, 경기 중 변경 불가, 플레이어 간 중복 선택 허용으로 설정합니다.
- 서버는 Character ID와 고유 스킬의 연결을 관리하고 선택 및 스킬 사용 요청을 검증합니다.
- 스킬의 구체적인 효과와 수치는 별도 기획에서 확정합니다.
- Phase 3에서 캐릭터 선택과 외형 동기화를 구현하고, Phase 4에서 고유 스킬 3종을 완성합니다.

## Phase 1. 네트워크 및 서버 기반 구축

**Sprint 01–03**

목표: 클라이언트가 서버에 접속하고, 여러 플레이어가 동일한 게임 월드에 참여할 수 있는 기반 구축

### Sprint 01. 네트워크 통신

- TCP 연결 및 패킷 송수신
- UDP 실시간 통신
- 패킷 직렬화 및 역직렬화
- 연결 종료 및 타임아웃 처리

### Sprint 02. 서버 게임 루프

- 고정 Tick 기반 GameLoop
- Room 및 Player 관리
- 게임 상태와 네트워크 처리 분리
- 입력 큐 및 게임 이벤트 처리

### Sprint 03. 게임 세션

- 플레이어 입장 및 퇴장
- Player ID 발급
- 플레이어 생성 및 제거
- Room 내 상태 브로드캐스트

**완료 조건:** 여러 Unity 클라이언트가 동일한 Room에 접속하고 서로의 캐릭터를 확인할 수 있다.

## Phase 2. 서버 권위형 캐릭터 시스템

**Sprint 04–06**

목표: 서버가 플레이어의 위치, 물리 및 애니메이션 상태를 직접 시뮬레이션

### Sprint 04. 이동 및 물리

- WASD 이동 및 시점에 따른 이동 방향
- 점프, 중력, 착지
- 서버 충돌 판정
- 이동 속도 및 가속도 검증

### Sprint 05. 애니메이션 상태 시스템

- 서버 캐릭터 상태 머신
- Idle, Run, Jump, Fall, Land
- 애니메이션 시작 Tick 및 지속 시간 관리
- 애니메이션 전환 가능 여부 검증
- Unity Animator 상태 동기화

### Sprint 06. 플레이어 상태 동기화

- 서버 Snapshot 생성 및 전송
- 위치, 회전, 속도, 애니메이션 상태 동기화
- Remote Player Interpolation
- 서버 상태 기반 위치 보정

**완료 조건:** 서버에서 플레이어 이동과 애니메이션 상태를 결정하고 모든 클라이언트에서 일관되게 표시한다.

## Phase 3. 전투 및 데스매치

**Sprint 07–09**

목표: 서버에서 전투를 판정하고 실제 데스매치 한 판을 플레이할 수 있도록 구현

### Sprint 07. 무기 및 사격

- 무기 데이터 및 탄약 관리
- 히트스캔 사격
- 서버 명중 및 피해 판정
- 발사 간격, 재장전 검증
- 사격·재장전 애니메이션 상태 관리

### Sprint 08. 전투 상태 시스템

- 체력 및 피해 처리
- 피격 및 경직 상태
- 사망 애니메이션 및 상태 전환
- 리스폰 처리
- 킬 및 데스 기록

### Sprint 09. 데스매치 게임 모드

- Waiting / Playing / Finished
- 캐릭터 3종 데이터 및 Character ID 정의
- 경기 시작 전 캐릭터 선택 UI 및 서버 선택 검증
- 선택한 캐릭터의 외형 동기화 및 리스폰 시 선택 유지
- 경기 시작 및 종료
- 제한 시간 및 점수 집계
- 스폰 위치 선정
- 결과 화면 및 재경기

**완료 조건:** 4명이 캐릭터 3종 중 하나를 선택해 서버에 접속하고 사격, 처치, 리스폰이 가능한 데스매치 한 판을 완료한다. 고유 스킬은 Phase 4에서 추가한다.

## Phase 4. 하이퍼 TPS 액션 시스템

**Sprint 10–11**

목표: 빠른 이동 및 스킬 중심의 하이퍼 TPS 전투 구현

### Sprint 10. 하이퍼 무브먼트

- 대시 및 슬라이딩
- 공중 이동 제어
- 이동 능력 쿨다운
- 서버 이동 능력 검증
- 이동 애니메이션 전환 및 취소

### Sprint 11. 스킬 및 애니메이션 전투

- 캐릭터별 고유 액티브 스킬 1개씩, 총 3종 구현
- 공통 스킬 입력 및 선택한 캐릭터에 따른 서버 스킬 실행
- 스킬 소유 여부, 생존 상태 및 쿨다운 검증
- 스킬 상태 머신
- 선딜, 발동, 후딜 관리
- 애니메이션 기반 공격 판정 타이밍
- 스킬 히트박스 및 충돌 판정
- 스킬 취소 및 상태 전환 규칙
- 스킬 발동 이벤트 및 지속 상태 동기화
- Unity 스킬 연출 및 쿨다운 UI
- 사망 및 리스폰 시 스킬 상태와 쿨다운 처리 규칙

**완료 조건:** 캐릭터 3종이 각각 자신의 고유 스킬 1개를 사용할 수 있고, 빠른 이동과 스킬을 활용한 전투가 서버 판정에 따라 정상적으로 동작한다. 다른 캐릭터의 스킬 사용 및 쿨다운 중 재사용 요청은 거부한다.

## Phase 5. 네트워크 동기화 고도화

**Sprint 12–13**

목표: 네트워크 지연 환경에서도 부드럽고 정확한 플레이 경험 제공

### Sprint 12. Client Prediction

- 클라이언트 이동 예측
- 입력 히스토리 관리
- Server Reconciliation
- 서버 보정 및 재시뮬레이션
- 애니메이션 예측 및 보정

### Sprint 13. Lag Compensation

- 서버 플레이어 히스토리 저장
- 발사 시각 검증
- 과거 히트박스 재구성
- 지연 보상 명중 판정
- Snapshot Delta Compression 및 전송 최적화

**완료 조건:** 네트워크 지연과 패킷 손실 환경에서 플레이어 이동 및 사격이 안정적으로 동작한다.

## Phase 6. 최적화 및 배포

**Sprint 14–15**

목표: 서버 성능과 안정성을 검증하고 외부에서 플레이할 수 있는 빌드 완성

### Sprint 14. 성능 및 부하 테스트

- 가상 클라이언트 구축
- 동시 접속 및 전투 테스트
- 서버 Tick 처리 시간 측정
- CPU, 메모리, GC 모니터링
- 패킷 송수신량 및 병목 분석

### Sprint 15. 배포 및 통합 테스트

- 게임 서버 배포 자동화
- 서버 설정 및 로그 관리
- Unity 클라이언트 빌드
- 실제 다중 PC 플레이 테스트
- 캐릭터 3종의 중복 선택, 고유 스킬 상호작용 및 리스폰 통합 테스트
- README 및 기술 문서 작성

**완료 조건:** 외부 네트워크에서 최대 8명의 플레이어가 서버에 접속해 데스매치를 정상적으로 진행한다.

## 개발 시 핵심 설계 원칙

1. 서버 권위: 클라이언트는 입력을 전달하고 서버가 게임 상태를 확정한다.
2. 애니메이션: 서버는 애니메이션과 연결된 게임플레이 상태 및 타이밍을 관리하고 Unity가 실제 애니메이션을 재생한다.
3. 물리: 서버가 충돌과 이동을 판정하며, 클라이언트는 예측을 통해 지연을 줄인다.
4. 동기화: 모든 상태를 매번 전송하지 않고 Snapshot과 이벤트를 적절히 구분한다.
5. 검증: 각 Phase 종료 시 멀티 클라이언트 통합 테스트를 수행한다.

개발 기준점은 **Phase 3 완료 시점**입니다. 여기까지 구현하면 서버 권위형 데스매치가 실제로 플레이 가능한 수준이 되고, 이후 Phase 4~6에서 하이퍼 TPS 특유의 액션과 네트워크 품질을 완성할 수 있습니다.
